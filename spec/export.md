# Keevo 导出文件

- **版本**：1.1
- **状态**：**已冻结**（2026-11-20，经第五轮评审：预审、正式评审与六次确认，[处理记录](../docs/reviews/)）。冻结的是文件格式：§2 的 JSON（`"version": 1`）与 §3 的加密文件（版本字节 `0x01`）。§3 中导出密码的强度要求与估计算法、§4 的 CSV 列与读入其他来源时的规整不属于格式，可以随实现改进（[README.md](README.md)"不属于格式"）。
- **参考实现**：
  - `crates/keevo-crypto` 的 `export` 模块（加密文件的封装与打开）
  - `crates/keevo-core` 的 `export` 模块（写出）与 `import::keevo`（读入）
- **相关**：[crypto.md](crypto.md) §5（KDF 参数）、§6（口令的 NFKD 规范化）；[vault-format.md](vault-format.md)（字段类型与用途的取值）

导出文件用于把条目带到另一台 Mac、另一个 Keevo 账户，或其他密码管理器。它不是备份：备份是数据库的副本，
与保险库同等加密（[docs/sync.md](../docs/sync.md) §2）；导出文件只有条目的**当前内容**，没有历史版本、
并发版本、删除记录与本机状态（浏览器配对、SSH Agent 的授权与策略）。

## 1. 三种格式

| 格式 | 扩展名 | 内容 | 保护 |
|---|---|---|---|
| Keevo 加密文件（推荐） | `.keevo-export` | §2 的 JSON，按 §3 加密 | 导出密码（§3"导出密码"，与主密码无关） |
| JSON（明文） | `.json` | §2 的 JSON | 无 |
| CSV（明文） | `.csv` | 只有登录：`name,url,username,password,note,totp` | 无 |

**每次导出前**（任何格式，包括加密文件），Keevo 重新验证用户（Touch ID 或主密码）：拿到文件和导出密码的人就能读出
全部条目，导出密码又由操作者自选。验证只能用于导出，是一次性的，2 分钟内有效，并绑定当时的解锁：锁定之后又解锁，
即使还在 2 分钟之内也作废。界面先选保存位置，验证通过后立即写入。明文导出另外提示明文文件的风险。
不导出最近删除中的条目。

**不导出的内容**：附件（§2）；归档状态（`archived`）；条目的安全提醒设置（`security_alerts`）；SSH Agent 的策略
（本机记录，`ssh-agent.md` §4.1）；条目的使用统计与创建时间（本机记录 `item_stats`，`crypto.md` §8.8）；历史版本、并发版本与删除记录。归档的条目照常导出，导入后不再是归档状态。

## 2. JSON

UTF-8，一个对象：

```json
{
  "format": "keevo-export",
  "version": 1,
  "exported_at": "2026-11-19T14:32:00Z",
  "vaults": [
    {
      "name": "个人",
      "items": [
        {
          "type": "login",
          "title": "GitHub",
          "favorite": true,
          "tags": ["工作"],
          "sections": ["安全"],
          "fields": [
            { "kind": "text", "label": "用户名", "purpose": "username", "value": "octocat" },
            { "kind": "concealed", "label": "密码", "purpose": "password", "value": "…" },
            { "kind": "url", "label": "网站", "value": "https://github.com" },
            { "section": 0, "kind": "recovery_codes", "label": "恢复码", "codes": [{ "code": "…", "used": false }] }
          ]
        }
      ]
    }
  ]
}
```

| 键 | 说明 |
|---|---|
| `format` | 固定为 `keevo-export` |
| `version` | 本格式的版本，当前为 `1`。读取方遇到不认识的版本时拒绝 |
| `exported_at` | 导出时间，UTC，RFC 3339，只供显示 |
| `vaults[].name` | 保险库名称 |
| `items[].type` | 条目类型，取值同 vault-format（`login`、`email_account`、`secure_note`、`ssh_key`、`api_credential`、`database`、`environment`、`two_factor`） |
| `items[].title` | 标题 |
| `items[].favorite` | 收藏；为 `false` 时省略 |
| `items[].tags` | 标签；为空时省略 |
| `items[].sections` | 分区名称，按显示顺序；为空时省略 |
| `fields[]` | 字段，按显示顺序：先默认分区，再按分区顺序 |
| `fields[].section` | 所在分区在 `sections` 中的下标；默认分区省略 |
| `fields[].kind`、`label`、`purpose` | 取值同 vault-format；`purpose` 为空时省略 |
| `fields[].value` | 文本字段的值 |
| `fields[].entries` | `kv_list` 字段：`[{ "key", "value", "concealed" }]` |
| `fields[].codes` | `recovery_codes` 字段：`[{ "code", "used" }]` |

**读入**（Keevo 自己的导出文件）：
- **原样保留**：除本节列出的情形外，条目经导出再导入不变（第五轮评审 L6、确认评审 M2）：
  - 分区以 `sections` 数组中的**位置**为身份，同名的分区是不同的分区，不合并；
  - 标题、字段名、分区名、标签与值都不截断、不去首尾空白；空标题与值为空字符串的字段照样导入；
  - 条目的大小只受格式本身的上限（`vault-format.md` §1、§2）约束，超出时整次导入失败，不静默截断或丢弃。
- **数据的形态**：`value`、`entries`、`codes` 恰好出现一个，并与 `kind` 一致：`kv_list` 用 `entries`，`recovery_codes`
  用 `codes`，其余文本类型用 `value`。三者都没有的字段忽略；出现多个、或与 `kind` 不一致（包括 `kind` 为
  `attachment`）的字段不导入，在条目备注中说明个数，其余照常导入。
- **不认识的成员**：忽略。本格式用于交换，`version` 不变的修改只会增加读取方可以忽略的成员；影响含义的修改提升 `version`。

**资源上限**（所有来源的读取，`crates/keevo-core` 的 `import` 模块）：文件 512 MiB；JSON 至多 400 万个节点（解析之前
计数，不为恶意文件建立巨大的解析树）；50,000 个条目，超过即停止。这些上限是有界，不是低内存。

**其他来源**（1Password、Bitwarden、浏览器 CSV 等，不属于本格式）的导入另有规整，不适用于 Keevo 自己的文件：名称与普通值
去掉首尾空白；名称超过 200 字节（标签 256 字节）时截断；每个条目最多 1000 个字段、200 个分区、100 个标签；同名分区合并；
空标题用第一个网址的主机名或"导入的条目"。截断与超出上限都在条目的备注中说明，不静默发生。秘密值（`concealed`、
SSH 私钥）与多行文本（包括备注）一律原样保留。

**附件不导出**：导出文件只有文本内容。附件字段不出现在 JSON 中，需要时请在 Keevo 中逐个保存附件。

导入时，字段与分区按文件中的顺序重新编号（新的 ID 与排序键）；文件中有多个保险库时，每个条目加上标签
`Keevo · <保险库名>`，以便区分。

## 3. 加密文件

```
magic "KEEVOEXP"（8 字节）
version 0x01（1 字节）
KdfParams（29 字节，crypto §5.1 的编码）
nonce（24 字节，随机）
密文 || 认证标签（16 字节）
```

- `k = Argon2id(NFKD(导出密码), KdfParams)`，32 字节；口令的规范化与长度限制同 crypto §6。
- `key = HKDF-SHA256(ikm = k, salt = 空, info = "keevo/v1/export")`，32 字节。
- 算法为 XChaCha20-Poly1305；AAD 为密文之前的全部 62 字节（magic、version、KdfParams、nonce）。
- 明文为 §2 的 JSON，最长 256 MiB。
- 写出时使用新的随机 salt 与 crypto §5.2 的**默认** KDF 参数，不得上调：读取方会拒绝超出自己预算的文件（下一条），
  写出方上调参数，文件就可能在另一台设备上打不开。
- 读取时，KDF 参数超出本机自动执行预算（crypto §5.3）的文件直接拒绝，不询问：导出文件来自外部，
  不应让它决定消耗多少内存。认证失败时不区分"密码错误"与"文件被改动"。

**导出密码**：文件只受这个密码保护，没有账户密钥这一层，离线猜测的代价只有一次 Argon2id。以下要求都针对
**NFKD 规范化之后、实际进入 KDF 的口令**（crypto §6），而不是输入时的写法：
- 至少 10 个字符（Unicode 标量）；
- 不全是空白；
- 强度估计达到最高档"很强"（4 分，估计的猜测次数不少于 10¹⁰）。估计用 zxcvbn 的算法（`crates/keevo-core` 的
  `strength` 模块），只看前 1024 个字符（之后的部分不计入，只会低估），取以下几种估计中**最小**的：
  - 不超过 64 个字符时，zxcvbn 整段分析；
  - **LZ77 分解**：从头往后，与前面某处相同、不短于 4 个字符的片段记为一次复制，只按重复次数 × 复制来源的选择数
    计入；其余字符是新内容，每 64 个字符一段用 zxcvbn 估计，各段相乘，最多分析 128 个字符的新内容；
  - **近似周期**：原文是同一片段的重复（至少两份，删除可以让它比两份更短），与"这个片段无限重复"的编辑距离不超过 3
    （替换、插入或删除，改动可以在任何一份中），估计为片段 × 重复次数 × 每处改动（位置数 × 95）。基础片段的候选
    有四种来源：
    - 出现次数最多的片段（份数多时，总有完好的几份）；
    - 份数不超过 4 时，每一份所在的位置（前后错开最多 3 个字符）；
    - 两三份、每一份都有改动时，从第一份与另一份的差异中还原：每处差异取其中一份的字符；正好两份、在同一位置都被
      改动时，那个位置的字符逐个尝试小写字母、数字与 `@$!#*._-`；
    - **常见词**：基础片段就是某个词典中排名靠前的词，每一份都可能有改动——改成相同的字符、在不同位置删除、几份
      在同一位置都被改动。没有完好的一份时至少有两处改动，所以只看排名不超过 10¹⁰ / (2 × (95n)²) 的词（10 个
      字符时约 5540）。原文先要在结构上像重复（错开一个周期的前后两段差异很少），再按小写直接核对编辑距离。

    多个解释中按**总代价**取最小的，而不是改动最少的。

  这是一个**枚举模型**：攻击者依次枚举基础片段、重复次数与每处改动。按这个模型，在常见口令上重复、追加、插入、删除
  或替换几个字符、与另一个常见片段交替，猜测次数只比基础片段多一个小的因子，通常达不到"很强"。基础片段本身已有中等
  强度、再叠加改动时，按模型确实可能达到 10¹⁰，这时得到 4 分不是虚高。真正随机的长口令几乎没有长的重复，几乎全是
  新内容，不受影响。

这是对常见弱口令的**筛选**，不是可证明的熵下界："估计的猜测次数不少于 10¹⁰"不等于真实的猜测代价不低于此值。它也
**不保证完备**：上面的候选来源与为性能所做的剪枝（比较两份时差异不超过一半、跳过已找到周期的倍数、只尝试部分字符）
都是启发式的。第五轮的确认评审逐轮找到并修复了一些漏网的变体（L1、M1、N1、P1、Q1、Q2、R1、T1–T3），已知仍可能
漏网的包括：基础片段是几个模式的组合（例如名字加数字）而每一份都有改动，基础片段中有 l33t 替换或大写，以及剪枝排除的
情形（评审报告 T4、T5）。这些按普通缺陷继续改进；它们不改变文件格式，导出密码的筛选也不在冻结范围内。

界面实时显示强度，达到要求之前不能导出。读入时不检查导出密码的强度。

## 4. CSV

第一行为表头 `name,url,username,password,note,totp`，之后每个登录一行（RFC 4180：含逗号、引号、换行或首尾
空格的字段用双引号括起，引号写作 `""`）。取每个登录的第一个网址、用途为用户名 / 密码 / 备注的第一个字段，
以及第一个一次性密码字段（`otpauth://` URI 或 Base32 密钥）。其他类型的条目与其余字段不导出。

**读入其他来源的 CSV**（RFC 4180）：引号括起的字段结束之后，只能是逗号、换行或文件结尾；`"abc"def` 这样的
字段是格式错误，整个文件拒绝导入，而不是拼成 `abcdef`（第五轮评审 L6）。

**公式注入**（CWE-1236）：以 `=`、`+`、`-`、`@` 开头的值原样写出。在电子表格中打开时，这样的值可能被当作公式，
例如把同一行的密码拼进一个链接（第五轮预审 K18）。转义（例如在前面加 `'`）会改变值，导入其他密码管理器后密码就不对了，
因此不转义。CSV 只用于导入其他密码管理器：导出前的风险提示中说明"不要用电子表格打开"（设计稿"预审修复"）。
