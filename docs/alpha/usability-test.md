# Alpha 可用性测试方案

Alpha 验收（路线图 §8 第 4 项、§3.8"体验"）的执行方案：与 5 名目标用户做可用性测试。

## 1. 通过标准

| 指标 | 标准 | 计算方式 |
|---|---|---|
| 首次填充 | ≤ 5 分钟 | 每人单独计时，按 5 人的中位数判定；同时逐人记录，超过 10 分钟的逐一分析原因 |
| 关键任务成功率 | ≥ 90% | 成功的"人 × 任务"数 ÷ 总数。8 个关键任务 × 5 人 = 40，至少 36 个成功；"协助后完成"不算成功 |

判定方式已于 2026-11-23 确定（中位数；"协助后完成"不算成功），测试后不再改。

## 2. 参与者

- **人数与画像**：5 人，符合 docs/product.md §3 的首发画像：用 Mac 与 Chrome、在意隐私的开发者或技术用户。
- **背景搭配**：
  - 至少 2 人用过其他密码管理器（1Password、Bitwarden、Chrome 自带的等）；
  - 至少 1 人没有用过。
- **排除**：参与过 Keevo 开发或看过设计稿的人。
- **隐私**：不使用参与者真实的账户与密码。

## 3. 准备

- **设备**：一台测试用的 Mac，系统完整性保护开启，登记了参与者的指纹（或只用主密码，并在记录中注明）。每位参与者开始前恢复到干净状态：
  - 删除 `~/Library/Application Support/Keevo`；
  - 卸载 Keevo.app；
  - Chrome 使用新的用户配置。
- **Keevo.app**：打包产物（`scripts/package-macos.sh`），放在"下载"文件夹中，带隔离属性，与真实下载一致。
- **扩展**：尚未上架 Chrome 网上应用店，由主持人事先在开发者模式下加载 `apps/browser-extension/dist`，不计入任务。
- **测试网站与账户**：主持人事先注册的测试账户。至少准备：
  - 一个普通登录页；
  - 一个分步登录页（先输入邮箱）；
  - 一个注册页；
  - 一个开启了两步验证（TOTP）的账户，备好它的二维码。
- **导入样例**：一份 Bitwarden 的 JSON 导出或 1Password 的 1PUX 导出，内容为虚构数据。
- **开发者任务**：一台可以用 SSH 密钥登录的测试主机，或一个读取环境变量的示例脚本。
- **录屏与计时**：征得同意后录屏；主持人用秒表计时。

## 4. 流程（约 50 分钟）

1. **介绍**（5 分钟）：
   - 说明测试的是产品，不是参与者；
   - 请参与者边做边说出想法；
   - 主持人不回答"该怎么做"。
2. **任务**（35 分钟）：按下表顺序进行。卡住 3 分钟后，主持人可以给一次提示，结果记为"协助后完成"；再卡住 3 分钟记为"失败"，进入下一个任务。
3. **访谈**（10 分钟）：
   - 哪一步最困惑？
   - 和以前用的工具相比如何？
   - 最想要的改变是什么？
   
   另请参与者用 1–5 分评价"我会愿意日常使用"。

## 5. 任务

T0 不计入关键任务，单独记录；T1–T8 是关键任务。

| 编号 | 任务（对参与者的说法） | 成功的标准 | 计时 |
|---|---|---|---|
| T0 | 安装下载好的 Keevo 并打开它 | Keevo 的首次使用界面出现。记录 Gatekeeper"仍要打开"的步骤中遇到的问题 | 单独计时 |
| T1 | 用 Keevo 在测试网站上登录：先创建账户，再让浏览器能用它，添加这个网站的账户，最后在登录页用 Keevo 填入 | 测试网站登录成功，用户名与密码由 Keevo 填入 | **首次填充**：从第一次打开 Keevo.app 开始，到登录成功为止 |
| T2 | 在分步登录的网站上用 Keevo 登录 | 先填入邮箱，下一步再填入密码，登录成功 | 记录用时 |
| T3 | 在注册页注册一个新账户，用 Keevo 生成密码并保存 | 生成的密码填入注册页，账户存入 Keevo | 记录用时 |
| T4 | 在 Keevo 中找到某个条目（主持人说出名称），复制它的密码 | 剪贴板中是正确的密码 | 记录用时 |
| T5 | 为测试账户添加两步验证码，并在网站上用它登录 | Keevo 中出现验证码，网站上填入后登录成功 | 记录用时 |
| T6 | 锁定 Keevo，再解锁，然后再登录一次测试网站 | 解锁后填充成功 | 记录用时 |
| T7 | 把样例导出文件中的账户导入 Keevo | 导入完成，抽查的 3 个条目字段完整 | 记录用时 |
| T8 | 开发者任务，二选一：用 Keevo 中的 SSH 密钥登录测试主机；或用 `keevo run` 运行示例脚本，让它读到 Keevo 中的密钥 | 登录成功或脚本输出正确，密钥没有出现在终端或文件中 | 记录用时 |

## 7. 汇总与问题分级

5 人完成后汇总：

- 首次填充：5 个用时与中位数。
- 关键任务：40 个中成功的个数。
- 问题清单：按出现人数与严重程度排序。严重程度分三级：

| 严重程度 | 含义 | 处理 |
|---|---|---|
| 阻断 | 参与者无法完成任务，或误操作可能导致数据丢失、泄露 | Alpha 发布前必须修复 |
| 严重 | 需要提示才能完成，或明显拖慢 | Alpha 发布前修复，或写明理由推后 |
| 轻微 | 有困惑但能自行完成 | 记入待办 |

未达标时，修复阻断与严重的问题后，换新的参与者重测未达标的指标。
