# 自托管服务端（暂缓）

> **状态：暂缓，未排期。** 目前多设备同步由 iCloud 与文件夹同步承担（见 [../sync.md](../sync.md)）。本文只记录已经形成的思路，正式立项时需要重新评审。

## 1. 何时值得做

文件夹同步无法提供以下能力。当其中某项成为明确需求时，再考虑立项：

| 能力 | 文件夹同步的现状 | 服务端能带来什么 |
|---|---|---|
| 实时性 | 几秒到几分钟，取决于云盘客户端 | WebSocket 推送，亚秒级 |
| 新设备审批 | 只能事后通知 | 由服务端强制要求已有设备批准 |
| 与他人共享保险库 / 家庭 | 不支持 | 作为成员与公钥目录的协调方 |
| 不装云盘客户端的平台（如 Linux、Web） | 依赖 WebDAV/S3 直连 | 统一的同步端点 |
| CI 服务账号 | 不适用 | 受限令牌访问指定保险库 |

## 2. 已确定的设计约束

- **复用现有协议**：服务端作为又一种 `SyncStore` 实现，沿用相同的日志段、快照、签名与合并规则，服务端只额外提供协调能力。客户端的安全模型不变：服务端依然不可信，只看到密文。
- **认证**：OPAQUE（RFC 9807，`opaque-ke`）。输入由 2SKD 单独派生：`HKDF(K_p ‖ K_s, info = "keevo/v1/opaque")`，与 AUK 相互独立。服务器永远拿不到密码或任何密码等价物。
- **形态**：
  - Rust（axum + sqlx）单一静态二进制或容器镜像；默认 SQLite，可选 PostgreSQL；附件可放本地磁盘或 S3 兼容存储。
  - 支持 amd64 和 arm64，128 MB 内存可以运行。
- **隐私**：
  - 默认不记录 IP，不需要邮箱，使用邀请码注册，不调用任何第三方服务。
  - 管理员只能管理账户与查看存储用量，无法访问任何内容。
- **运维**：
  - 一条 `docker run` 即可启动。
  - 提供在线一致性备份；升级时自动执行数据库迁移，迁移前先备份。
  - 可选的 Prometheus 聚合指标，不含任何用户标识。
- **许可证**：AGPL-3.0-or-later（见 [../governance.md](../governance.md#1-许可证)）。
