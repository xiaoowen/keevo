# 路线图与实施方案

**估算前提**：
- 核心团队 2–3 名全职工程师（Rust/密码学、macOS/Swift、Web/扩展各一），外加兼职设计师；安全审计由外部完成。
- 如果是一个人推进，时间大约翻倍，并且优先保证 M1 的质量，而不是赶进度。

## 1. 里程碑总览

| 阶段 | 时长 | 目标 | 对外形态 |
|---|---|---|---|
| **M0 基础** | 6–8 周 | 规范、工程骨架、CI、设计系统 | 公开仓库与设计文档 |
| **M1 本地保险库（MVP）** | 4–5 个月 | macOS 应用 + Chrome 扩展 + SSH Agent + CLI，纯本地运行 | 内测 Alpha |
| **M2 云同步** | 3–4 个月 | iCloud 与文件夹同步、新设备加入、通行密钥、系统级自动填充；首次外部审计 | 公开 Beta |
| **M3 1.0** | 2–3 个月 | 修复审计问题、稳定性、文档、可复现构建 | 1.0 正式版 |
| **M4+ 扩展** | 持续 | iOS、共享保险库、更多浏览器与桌面平台 | — |

## 3. M1 本地保险库 MVP（4–5 个月）

### 3.1 范围

**包含**：
- **macOS 应用**：
  - 首次使用流程 + 应急包；主密码与 Touch ID 解锁；自动锁定。
  - 8 种条目类型 + 自定义字段 + 本地附件；搜索与过滤语法；快速访问；菜单栏。
  - 密码生成器；TOTP 与屏幕扫码；条目历史与回收站。
  - 安全中心（本地检查 + 可选的 HIBP 查询）。
  - 导入（1Password 1PUX、Bitwarden JSON、Chrome/Safari/Firefox CSV、KeePass KDBX 4）；导出；自动加密备份。
  - 简体中文与 English。
- **Chrome 扩展**：
  - 与桌面应用配对。
  - 弹窗内搜索、复制、填充；内联菜单。
  - 登录与 TOTP 填充；保存与更新；注册页生成密码。
  - 最小权限模式。
- **开发者能力**：
  - SSH Agent（Ed25519 / RSA / ECDSA、授权策略、`~/.ssh/config` 助手）。
  - Git 签名配置。
  - CLI（`read` / `run` / `inject` / `item` / `totp` / `generate` / `lock`）。
  - `keevo://` 引用；`.env` 导入导出。

**不包含**：同步、通行密钥、Safari 与系统级 AutoFill、共享、iOS、信用卡与身份类型。

**为同步提前做的准备**：M1 的数据模型已经采用修订图、记录级 HLC 时间戳和墓碑（见 [sync.md §2–§3](sync.md#2-本地存储模型sqlite)），因此 M2 开启同步时不需要做数据迁移。

| M1.1 | 4 周 | 基于修订图的条目增删改查全链路、锁定与解锁、Touch ID、主界面框架 |
| M1.2 | 4 周 | 全部条目类型与字段系统、搜索、生成器、TOTP |
| M1.3 | 4 周 | 扩展配对与填充、保存与更新、内联 UI 防护、自动填充回归语料库 |
| M1.4 | 3 周 | SSH Agent、CLI、密钥引用 |

### 3.3 验收标准

| 维度 | 标准 |
|---|---|
| 功能 | 每种条目类型都能创建、编辑、搜索、删除、恢复；回归语料库中前 100 个登录页的识别率 ≥ 95%；导入 1Password / Bitwarden 样例数据时字段零丢失 |
| 性能 | 满足 [product.md §6.1](product.md#61-性能预算以-1-万条目的测试保险库为基准) 的性能预算 |
| 安全 | 内部安全评审通过；所有解析器都有模糊测试目标，且连续 24 小时无崩溃；秘密泄露检测通过（日志、磁盘、崩溃转储中都没有明文） |
| 可靠性 | 迁移、备份、恢复测试全部通过；反复 `kill -9` 测试下数据零损坏 |
| 体验 | 与 5 名目标用户做可用性测试：首次填充 ≤ 5 分钟，关键任务成功率 ≥ 90% |

## 4. M2 云同步（3–4 个月）

设计见 [sync.md](sync.md)，决策背景见 [ADR-0001](adr/0001-file-based-cloud-sync.md)。

**交付物**：
- [ ] `keevo-sync`：
  - 日志段与快照、修订图合并、签名哈希链校验、高水位线防回滚、清理
  - `SyncStore` 抽象，以及文件夹实现
- [ ] iCloud 实现（Swift，基于 `NSFileCoordinator` 与 `NSMetadataQuery`）：
  - 处理按需下载、Apple ID 切换、空间已满
- [ ] 文件夹同步：
  - 覆盖 Dropbox、OneDrive、Google Drive、坚果云、Syncthing、NAS、外置硬盘
  - 针对各家云盘的设置引导与常见问题文档
- [ ] 设备管理：
  - 设备证书
  - 加入新设备（局域网配对、扫码、手动输入）
  - 新设备通知、撤销
  - 两种密钥轮换（修改主密码、应急轮换）
- [ ] 同步状态界面与异常处理（[ux.md §3.9–§3.10](ux.md#39-开启同步m2)）
- [ ] 通行密钥：
  - Chrome 扩展中的 WebAuthn 支持
  - macOS AutoFill 凭据提供扩展，覆盖 Safari 与原生应用
- [ ] 首次外部审计：
  - 密码学设计
  - `keevo-crypto`、`keevo-format`、`keevo-sync`
  - 设备与密钥轮换流程

**退出标准**：
- 云盘行为模拟测试跑满一百万个以上随机场景，覆盖乱序、延迟、半截文件、冲突副本、删除与回滚、长期离线、设备克隆等情况，结果为零数据丢失且最终一致。
- 篡改测试套件全部被客户端检测出来，包括注入、移植、重放、回滚、伪造设备、KDF 参数篡改。
- 真实环境长测：3 台 Mac 在 iCloud 与至少两家云盘上连续运行 2 周，自动化脚本随机编辑，结果一致。
- 审计发现的高危问题全部修复。

## 6. M4+ 方向

按当前优先级排列，会根据社区反馈调整：

1. **iOS**：
   - 复用 Rust 核心与 SwiftUI 组件，加上 AutoFill 扩展。移动端是大多数用户的硬需求。
   - iCloud 同步可以直接复用同一个容器。
2. **WebDAV 与 S3 直连同步**：方便 iOS 和不想安装云盘客户端的用户；可接入 Nextcloud、群晖、坚果云等。
3. **更多浏览器**：Firefox、Safari Web Extension、Edge 商店。
4. **Windows / Linux 桌面**：用 Tauri 或原生 UI，复用 Rust 核心。
5. **CXF 标准导入导出**：视生态进度，可以提前。
6. **共享保险库与家庭**：
   - 采用混合后量子 HPKE；成员公钥通过安全码比对验证。
   - 多人共享需要一个协调方：可以基于 iCloud 共享文件夹，也可以借此契机启动自托管服务端，届时单独评审。
7. **紧急访问与社交恢复**。
8. **自托管服务端**（暂缓，见 [future/self-hosted-server.md](future/self-hosted-server.md)）：只有当实时性、强制审批新设备、共享或 CI 服务账号成为明确需求时才立项。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 密码学或协议设计错误 | 致命 | 规范先行；外部评审；审计；只使用标准构造 |
| 数据丢失 bug | 致命（直接摧毁用户信任） | 条目历史、自动备份、迁移测试、云盘行为模拟测试；坚持"绝不静默删除" |
| iCloud 或云盘的文件同步不稳定（延迟、按需下载、行为在系统更新后变化） | 同步体验差 | M0 先做技术验证；单写者加不可变文件的设计能容忍乱序和重复；真实环境长测；如果 iCloud 文件同步实在不可靠，再评估以 CloudKit 作为 iCloud 专用的 `SyncStore` |
| 用户被锁在门外（忘记主密码且丢失应急包） | 严重 | 首次使用时强制保存应急包；主密码练习提醒；可选恢复密钥 |
| 范围蔓延 | 延期 | 严格守住 MVP 范围；新需求一律进 M4+ 待办池 |
| 自动填充兼容性差 | 体验差 | 回归语料库；提供"无法填充"上报工具（用户主动提交脱敏的表单结构，不含任何值） |
| Chrome 商店审核或政策变化 | 发布受阻 | 遵循 MV3 最佳实践；权限最小化；提前提交审核；准备开发者模式安装文档作为后备 |
| Apple 平台变化 | 功能受限 | 跟进每年 WWDC；只使用公开 API |
| 维护者单点（bus factor） | 长期风险 | 尽早吸引核心贡献者；发布密钥由多人持有；关键知识全部文档化 |
| 与 1Password 的体验差距 | 影响采用率 | 设计系统先行；性能预算写进验收标准；可用性测试常态化 |
