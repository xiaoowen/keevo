# Keevo 体验设计

## 1. 体验原则

1. **安静的安全感**：锁定状态、同步状态、风险提示要清晰，但不打扰、不制造恐慌。
2. **键盘优先**：所有操作都能用键盘完成；全局快捷键唤起快速访问（Quick Access）。
3. **渐进披露**：新手看到的是简洁的界面；KDF 参数、网址匹配规则、Agent 授权策略等高级选项在需要时才出现。
4. **秘密默认隐藏**：显示秘密必须是一个有意的动作，离开即自动隐藏。
5. **一切可撤销**：删除进回收站，编辑有历史，导入可回滚。
6. **讲清取舍**：每个安全设置都说明"它能防什么、代价是什么"。
7. **原生感**：macOS 端遵循 HIG（侧边栏、工具栏、菜单、快捷键、拖放、服务菜单）；扩展遵循 Chrome 的交互习惯。

## 2. macOS 信息架构

主窗口采用三栏结构：**侧边栏 → 条目列表 → 条目详情**。

```
侧边栏
├── 全部条目
├── 收藏
├── 分类
│   ├── 登录 / 电子邮件账户 / 安全笔记
│   ├── SSH 密钥 / API 凭证 / 数据库凭证 / 环境变量
│   └── 双因素验证
├── 保险库（个人、工作、开发……）
├── 标签
├── 安全中心（显示待处理数量）
├── 开发者
│   ├── SSH Agent（状态、授权记录）
│   └── CLI 会话（已授权的终端）
└── 归档 / 最近删除
```

- **条目列表**：
  - 顶部是搜索框，支持模糊搜索与过滤语法：`type:ssh`、`tag:work`、`vault:开发`、`url:github.com`、`is:fav`、`is:conflict`，前加 `-` 表示排除（如 `-tag:archive`），`"…"` 括起来的是一个词。`is:weak`（弱密码）在安全中心检查完成后可用。
  - 列表项显示图标、标题、副标题（用户名或 Key ID）。
- **条目详情**：
  - 头部：图标、标题、收藏、编辑。
  - 字段行：每行带复制按钮，秘密字段另有显示和大字显示按钮。
  - TOTP：验证码配倒计时环。
  - 安全区：强度、复用、泄露。
  - 历史版本、关联条目、附件。

其他界面：

| 界面 | 作用 |
|---|---|
| 菜单栏图标 | 显示锁定状态；快速访问、生成密码（锁定时也可用）、打开 Keevo、立即锁定、设置、退出。可在"设置 → 通用"中关闭；显示时关闭窗口后 Keevo 继续运行 |
| 退到后台 | `⌘Q` 不结束 Keevo，而是退到后台：隐藏窗口（状态保留），显示菜单栏图标时同时隐藏程序坞图标；浏览器扩展、命令行工具、SSH Agent 与快速访问照常可用，解锁状态不变、照常自动锁定。窗口再次出现时恢复程序坞图标。真正退出用 `⌥⌘Q`，或菜单栏、程序坞中的"退出" |
| 列表排序 | 列表栏顶部的排序按钮：标题、创建日期、修改日期、使用频率、最近使用，可反转顺序；选择记在这台 Mac 上，有搜索词时按相关度排列。"使用"指在 Keevo 或快速访问中复制、浏览器填充、`keevo read` / `keevo run` 取用与 SSH 签名；使用记录与创建时间加密存成本机记录（`spec/crypto.md` §8.8），不随同步与导出 |
| 检查更新 | 默认开启，每天一次读取 GitHub 上公开的发布列表（`docs/governance.md` §5）。有新版本时"设置 → 通用"与侧边栏底部提示，点击打开发布页，按安装说明下载并核对；不自动下载、不自动安装。应用菜单中的"检查更新…"立即检查。正在运行预发布版本时也提示更新的预发布版本 |
| 快速访问浮窗 | 全局快捷键唤起（默认 `⌥⌘K`，可在"设置 → 通用"中修改），类 Spotlight。搜索后：`↩` 复制密码，`⌘C` 复制用户名，`⌥↩` 复制验证码，`⌘O` 在主窗口打开，`esc` 关闭；没有输入时列出收藏。浮窗不激活 Keevo，复制后可以直接在原来的应用中粘贴；锁定时先解锁。快捷键用系统的热键登记，不需要辅助功能权限，也不监听其他按键 |
| 锁屏 | Touch ID 按钮 + 主密码输入；显示"为什么需要主密码"（如重启后、超过 14 天） |
| 设置 | 通用、安全、同步与设备、浏览器、开发者、备份、高级 |
| 同步状态 | 侧边栏底部常驻一行：已同步 / 同步中 / 等待 iCloud 下载 / 已暂停（附原因）。点击打开"同步与设备" |

## 3. 关键流程

### 3.1 首次使用（目标 ≤ 3 分钟）

1. **欢迎**：用三句话讲清承诺——数据只在你的设备上；没有人能读取，包括我们；代码开源可验证。
2. **选择**：创建新保险库 / 从其他密码管理器导入 / 加入已有账户（M2，见 §3.10）。
3. **设置主密码**：
   - 本地实时显示强度反馈，推荐使用生成的密码短语（4 个 EFF 单词）。至少 10 个字符，强度至少"一般"：常见密码及其简单变体不能用作主密码。
   - 明确告知：忘记主密码且丢失应急包，数据将无法恢复。
4. **账户密钥与应急包**：
   - 生成账户密钥（Secret Key）和 PDF 应急包，内含账户密钥、二维码（只含账户密钥）、账户 ID、主密码书写处。PDF 只在内存中生成，由用户选择保存（权限 0600）或打印。
   - 提供保存与打印；需勾选"我已妥善保存"才能继续。之后可以在"设置 → 安全"中重新保存（先重新验证）。
   - 首次使用期间不因闲置自动锁定；中途锁定或退出时，解锁后从上次的步骤接着进行。
5. **开启 Touch ID**：推荐默认开启。
6. **连接浏览器**：检测已安装的 Chromium 系浏览器，一键打开扩展商店页面；扩展装好后自动发起配对（§4.4）。
7. **导入或添加第一个条目**。完成页给出三个下一步：安装扩展 / 设置 SSH Agent / 试试快速访问。
8. **之后**：第 3 天、第 7 天，之后每月一次，提示"练习一次主密码"，可关闭，防止只用 Touch ID 导致遗忘。

### 3.2 解锁

- **默认用 Touch ID**。以下情况必须输入主密码：
  - 重启后的首次解锁。
  - 距上次输入主密码超过 14 天（可设为 1–30 天）。
  - 指纹集合发生变化。
  - Touch ID 连续失败 3 次。
- **锁屏要说明原因**，例如"Mac 重启后需要输入一次主密码"，避免用户困惑。

### 3.3 网页登录（自动填充）

1. 聚焦用户名或密码框后，输入框右侧出现 Keevo 小图标（可在设置中关闭）。
2. 点击图标或按扩展快捷键，弹出内联菜单，列出与当前网站匹配的条目。菜单显示匹配的域名；若在 iframe 中，显示 iframe 的域名。
3. 选择条目 → 若 Keevo 已锁定，弹出 Touch ID → 填充用户名与密码。如果网站下一步要求 2FA，自动提供该条目的验证码。
4. **无匹配时**：
   - 提供"搜索全部条目"和"新建登录"。
   - 向不匹配的网站填充需要二次确认，并提示可能是钓鱼网站。

### 3.4 保存与更新

- **保存**：表单提交后，页面顶部出现保存栏（扩展自有 iframe）："保存这个登录到 Keevo？"，显示网站与用户名。保存到第一个保险库（选择目标保险库待后续版本）；Keevo.app 中出现"「浏览器名」保存了新的登录"的提示。
- **更新**：在修改密码的表单上提交新密码时，提示"更新 Keevo 中「条目」的密码？"。点"更新"后 Keevo.app 再请用户确认一次，旧密码进入密码历史。普通登录表单不提示更新（扩展不知道已保存的密码，无从判断是否改过）。
- 刚由 Keevo 填入、没有改动的密码不提示；"此网站不再提示"记在扩展中。只在标准模式下工作。
- **注册**：在注册页识别到 `new-password` 字段时，内联提供生成的强密码，遵循网站的密码规则库（如长度与字符集限制）。

### 3.5 添加 2FA

1. 网站展示二维码。
2. 在条目中点击"添加一次性密码"，选择"扫描屏幕二维码"（macOS）或扩展中的"扫描当前页面"。
3. 自动识别后显示当前验证码，供网站完成验证 → 保存。

### 3.6 SSH Agent 与 Git 签名

1. **开启 Agent**：在"设置 → 开发者 → SSH Agent"中开启。Keevo 生成要加入 `~/.ssh/config` 的配置（`IdentityAgent` 指向 `~/.keevo/agent.sock`），**先展示改动**，确认后写入，原文件备份。
2. **新建密钥**：默认 Ed25519。点"添加到 GitHub"会复制公钥并打开 GitHub 的 SSH 设置页，扩展可帮忙填写表单。
3. **授权**：终端执行 `git push` 时，Keevo 弹出"iTerm2 中的 `ssh` 请求使用密钥『GitHub』"→ Touch ID。按策略在本会话内免重复授权。
4. **Git 签名**：一键配置 git 的 SSH 签名，执行前展示将运行的命令。

### 3.7 `keevo run`

```console
$ cat .env.keevo
DATABASE_URL=keevo://dev/postgres-local/connection_string
OPENAI_API_KEY=keevo://dev/openai/credential

$ keevo run --env-file .env.keevo -- npm run dev
```

- 首次在某个终端使用时，弹出 Touch ID 授权，显示终端应用与将要执行的命令。
- 子进程拿到解析后的环境变量。
- 输出中如果出现秘密值，会被遮蔽为 `<concealed by keevo>`。

### 3.8 锁定

- **触发**：
  - 闲置 N 分钟（默认 10）。
  - 系统睡眠、屏幕锁定、切换用户。
  - 手动锁定（菜单栏或快捷键）。
- **锁定时**：
  - 清空内存中的密钥与解密缓存，界面切到锁屏。
  - 扩展收到锁定事件并清空界面。
  - CLI 会话失效。
  - 之后的 SSH Agent 请求会先触发解锁提示。

### 3.9 开启同步（M2）

1. 打开"设置 → 同步与设备 → 开启同步"，选择同步位置：
   - **iCloud（推荐）**：在 iCloud 云盘中创建「Keevo」文件夹，同一 Apple ID 下的设备都能使用。界面提示：这个文件夹里是加密数据，请不要手动修改或移动。
   - **选择文件夹…**：例如 Dropbox、OneDrive、坚果云的同步文件夹，或 Syncthing、NAS、外置硬盘。
2. 一屏说清三件事：
   - 同步的内容全部端到端加密，Apple 和云盘厂商都无法读取。
   - 同步速度取决于 iCloud 或云盘，通常几秒到几分钟。
   - 加入新设备需要主密码和账户密钥，请确认应急包放在手边。
3. 如果选的是云盘文件夹，提示把它设为"始终保留在此设备"，并给出该云盘的设置方法。
4. 完成后，侧边栏底部的同步状态显示"已同步"。

### 3.10 在另一台 Mac 上加入（M2）

1. 在新 Mac 上选择"加入已有账户"，然后选择 iCloud（自动发现账户）或同一个文件夹。
2. 获取账户密钥，界面按推荐程度排列：
   - **用旧 Mac 配对**：在旧 Mac 上点"添加设备"，两边显示同样的 6 个词，确认一致并在旧 Mac 上通过 Touch ID 授权。
   - **扫描二维码**：扫描旧 Mac 屏幕上或应急包上的二维码。
   - **手动输入**：输入应急包上的账户密钥。
3. 输入主密码，显示同步进度，完成后开启 Touch ID。
4. 旧 Mac 弹出通知："新设备『MacBook Air』已加入"。通知里提供"这不是我的设备"按钮，点击后直接进入撤销与应急轮换流程。

**同步异常时**（如发现回滚或篡改）：
- 显示"注意"级横幅，用平实的语言说明发生了什么，并说明本地数据安全无损。
- 给出可执行的选项：查看详情、暂停同步、重新同步。

## 4. Chrome 扩展体验

### 4.1 弹窗

- 顶部：搜索框。先在当前网站的登录中筛选；协议 v3 起也搜索其他网站的条目，分为"当前网站"与"其他网站"两组。每次解锁后第一次搜索其他网站的条目，需要点"在全部条目中搜索"并在 Keevo 中允许，到下次锁定前不再询问；其他网站的条目只能在 Keevo 中打开，不能在扩展里填充。
- 条目详情：复制、填充、查看验证码、在 Keevo 中打开。
- 底部："生成密码"（在扩展内生成，可复制或填入网页的新密码框，提交后照常询问保存）、"新建登录"（为当前网站保存，只保存网站地址）、"在 Keevo 中打开"。
- 支持全键盘操作。

### 4.2 内联菜单

- 由输入框图标、在空输入框中按 ↓，或快捷键（⌘⇧L）唤起；↑↓ 选择，回车填充，Esc 关闭。
- 顶部显示"填充到 <输入框所在的网站>"；输入框在跨域 iframe 中时，写明嵌入关系并要求再点一次确认。
- 显示匹配条目；验证码输入框（`autocomplete="one-time-code"`）旁的菜单填入一次性密码。没有匹配时说明 Keevo 只在保存的网站上填充，网址对不上可能是仿冒网站。"生成密码"（注册页）和"搜索全部"需要协议 v2。
- 渲染在扩展自有的 iframe 里，页面脚本无法读取其内容（防护细节见 [security.md §12](security.md#12-浏览器扩展专项防护)）。

### 4.3 保存栏

- 页面顶部的横幅（扩展 iframe，与内联菜单相同的点击劫持防护）。
- 可选择"保存"、"更新"、"不保存"或"此网站不再提示"；Esc 关闭。提交的密码只留在扩展的内存中，3 分钟后丢弃。

### 4.4 与桌面应用配对

1. 扩展首次连接桌面应用时，两端同时显示一组 6 个词的配对码。
2. 用户在桌面应用中确认两端一致，配对即建立。
3. 之后自动连接。
4. 已配对的浏览器可以在"设置 → 浏览器"中查看与撤销。

### 4.5 两种权限模式

| 模式 | 权限 | 体验 |
|---|---|---|
| 标准模式 | 读取网站数据（用于内联图标与保存检测） | 完整体验 |
| 最小权限模式（安装后的默认） | 仅 `activeTab` | 只能点扩展图标或按快捷键（⌘⇧L）填充；没有内联图标和自动保存提示 |

安装时不申请网站权限。用户在弹窗中点"开启"在输入框旁显示 Keevo 图标时，Chrome 才询问网站权限；随时可以在弹窗中关闭。

### 4.6 异常状态

- **未安装桌面应用**：引导下载。
- **应用未运行**：自动唤起应用。
- **应用已锁定**：弹窗中的"用 Touch ID 解锁"请 Keevo 来到前台并直接请求 Touch ID；这次需要主密码时按钮为"在 Keevo 中解锁"。解锁后 Keevo 回到浏览器，弹窗自动重新打开。设计稿见"扩展 · 弹窗：搜索、生成密码、新建登录与解锁"。

## 5. 安全交互规范

| 场景 | 规范 |
|---|---|
| 秘密字段显示 | 默认显示 `••••`。点击后显示；切换条目、窗口失焦或 30 秒后自动隐藏。"大字显示"逐字符分色，区分数字、字母与符号，便于手动输入 |
| 复制 | 显示清除倒计时（默认 90 秒）。只有剪贴板内容仍是 Keevo 写入的值时才清除。写入时标记 `org.nspasteboard.ConcealedType` / `TransientType`，遵守该约定的剪贴板管理器会忽略这些内容 |
| 重新验证 | 查看 SSH 私钥、导出、修改主密码、查看恢复码、关闭 Touch ID、解除浏览器配对，都需要重新进行 Touch ID 或主密码验证 |
| 破坏性操作 | 删除进回收站并提供"撤销"；永久删除需二次确认 |
| 风险提示 | 分三级：信息 / 注意 / 危险。危险操作（如向不匹配的域名填充）需显式确认，文案说明具体风险 |
| 屏幕共享 | 可选（默认关闭）：Keevo 的窗口不允许被截屏或共享（`NSWindow.sharingType = .none`）。说明中写明只对遵守这一设置的软件有效，不能防范本机的恶意软件 |

## 6. 文案与语气

- **精确、平静、不吓人**：说清"这能防止什么"，而不是空洞地说"非常安全"。
- **少用术语**：必要时附"了解更多"。示例：
  - ❌ "解密失败：AEAD tag mismatch"
  - ✅ "这个条目的数据似乎被篡改或损坏了，Keevo 已阻止打开它。你可以从历史版本恢复。"（技术细节放在诊断信息中）
- **术语表**（中英统一）：

| English | 中文 |
|---|---|
| Vault | 保险库 |
| Item | 条目 |
| Master Password | 主密码 |
| Secret Key | 账户密钥 |
| Emergency Kit | 应急包 |
| Quick Access | 快速访问 |
| Security Center | 安全中心 |
| One-time password | 一次性密码 / 验证码 |
| Passkey | 通行密钥 |
| Secret reference | 密钥引用 |

- **界面语言**：简体中文与英文。中文是源语言：界面代码中的文字写成 `tr("模板", 参数…)`（macOS）或 `t("模板", 参数…)`（扩展），英文翻译在 `apps/macos/Localization/en.json` 与 `apps/browser-extension/i18n/en.json`，模板中的 `{}` 依次对应参数，英文可以用 `{0}`、`{1}` 调整语序。`scripts/i18n.py check` 检查翻译是否完整、占位符个数是否一致，`gen` 生成代码中的表。
  - **macOS**：跟随系统（系统首选语言是中文时用中文，其他语言都用英文），或在"设置 → 通用"中指定，重新打开后生效。
  - **扩展**：跟随浏览器的界面语言；扩展名称与说明用 Chrome 的 `_locales`。
  - **保险库中的数据**：条目类型模板的默认字段名、分区名与默认保险库名"个人"保存在保险库中，显示时按界面语言翻译（`apps/macos/Localization/data-labels.txt`）；用户自己起的名称原样显示。
  - 截图程序可以用 `KEEVO_LANG=en scripts/snapshots.sh` 渲染英文界面。

## 7. 设计系统

- **设计令牌**：颜色、字体、间距、圆角、动效以 `design/tokens/*.json` 为单一来源，生成 Swift 与 CSS 两套产物，保证桌面应用与扩展视觉一致。规范、取舍与组件清单见 [design/README.md](../design/README.md)。
- **对比度**：所有颜色组合由生成脚本按 WCAG 2.2 校验，不达标即构建失败，报告见 [design/contrast.md](../design/contrast.md)。
- **高保真设计稿**：v0 包含设计系统总览、锁屏、主窗口（浅色）、开发者条目（深色）、扩展弹窗三种状态、内联菜单与钓鱼拦截，目前保存在维护者的设计画布中，公开后在此附链接。
- **视觉**：
  - 以中性色为主，搭配单一品牌色；支持浅色、深色与高对比。
  - macOS 26+ 的 Liquid Glass 材质用于工具栏与浮窗；内容区保持实色，保证可读性。
- **网站图标**：默认在本地生成（首字母 + 颜色）。获取网站 favicon 为可选功能，因为它会向图标来源暴露你有账户的域名。开启时会向用户说明这一点。
- **动效**：克制，只用于状态变化（锁定/解锁、复制成功、验证码刷新），并遵循"减弱动态效果"设置。
- **核心组件**：字段行、秘密字段、TOTP 倒计时环、密码强度条、条目列表项、风险横幅、空状态、配对码视图、授权弹窗。v0 已在代码中实现网站图标、秘密值、字符分色与大字显示、提示横幅、配对码（`apps/macos/Sources/KeevoUI/Components.swift`、扩展 `popup.css`）。

## 8. 可访问性

- VoiceOver 覆盖所有界面。朗读秘密字段前需要确认，避免在公共场合被外放。
- 全键盘导航，焦点状态清晰可见。
- 对比度达到 WCAG AA。
- 信息不只靠颜色传达：强度、风险等级同时使用图标与文字。
