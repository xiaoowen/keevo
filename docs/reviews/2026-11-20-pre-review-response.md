## 3. 回答预审的问题

1. **备份的完整性**：M2 之前不对备份做认证，只做结构校验与逐行导入（K1）。被改写的备份因此最多等同于"一份更旧的备份"，不能改变 Keevo 此后的行为。整个备份的认证与同步格式一起在 M2 定义，用 ASK 派生的密钥并记录 `epoch`。
2. **附件在 M2 的形态**：作为独立的同步对象。因此这次冻结前定下了：只封装一次与内容承诺（S2）、回收条件（S4）、换保险库即复制（K23）。
3. **重建时的附件**：不是有意的。现在复制为新附件（K5）。原规范中的"已知限制"删除。
4. **导出口令**：采用强度下限（"很强"），不默认生成随机口令，也不把账户密钥作为第二因子。导出文件常用于带到另一个账户，那里没有这把账户密钥。
5. **泄露检查的范围**：是，忽略了提醒的条目不再查询（K16）。
6. **SSH Agent 策略的归属**：本机状态。策略已移到本机记录（K17），export.md 的说法因此成立。
