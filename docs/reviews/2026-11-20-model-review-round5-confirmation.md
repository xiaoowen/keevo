## 3. 调整过的测试与导出向量

**两项测试的语义调整可以接受。**

- `review5_l5_attachment_gc_retries_after_failure`：编辑已经提交，后续回收失败不报编辑失败合理。测试仍检查故障时附件留下、故障移除后重开解锁能回收，保留了原先关心的“失败后不能永久失去重试”的证据。但只覆盖单条目，不能排除 M6。
- `review5_l8_failed_restore_leaves_state_consistent`：既然约定失败保持原状，核心仍解锁且旧句柄可用正是正确断言；无需坚持锁定并清零。它证明原先的分裂状态已消除，不能替代导出能力的并发检查。另一项旧测试虽通过，其断言说明仍写“恢复失败导致锁定”，应改为“再次解锁建立新代次”；只是测试注释修正。

**独立导出向量足以作为加密封装字节格式的冻结证据。** Python 独立实现 Argon2id、NFKD、HKDF 和 XChaCha20-Poly1305；Rust 逐字节比较完整输出、核对 62 字节 AAD、打开全部正例，并按期望错误拒绝九个反例。普通 JSON、NFKD 等价口令、空明文以及 magic/version/salt/nonce/密文/tag/截断/KDF 非法值均覆盖。`generate_vectors.py --check` 和 Rust `vectors::export_files` 均通过。

这里验收的是封装。空明文是密码学 API 边界测试，不代表合法业务 JSON；向量也不证明口令筛选、JSON 往返、重新验证或本机 KDF 预算策略。可再补“合法但不同的 m/t/p”和默认参数向量、合法范围内 KDF 参数篡改认证失败样例，但本轮不把这些增补列为 S7 的冻结阻塞。

## 4. 新发现

### M1：重复段仍能把常见弱口令推到导出最高档

- **位置**：`crates/keevo-core/src/strength.rs:104`；`spec/export.md:127`。
- **问题**：重复识别生效后，每个窗口仍乘 2；首段被 64 字符边界截断后的估计再乘这些因子，仍会虚高到 4 分。
- **前提**：用户选择重复弱口令并依赖“很强”筛选；导出文件被他人获得。
- **影响**：常见基础词加重复次数即可构造的口令被允许保护全部导出内容；不是 Argon2id 或 AEAD 被破解。
- **严重程度**：**中**。
- **建议**：重复模式作为整体估计，不能每个重复窗口累乘独立成本；对长输入采取保守低估，并删除当前算法的过强说明。
- **证据**：`review5c_m1_repetition_does_not_reach_export_threshold` 失败。`"password123".repeat(93)` 获得约 `3.72×10¹⁰` 次估计、4 分并可导出；另四种重复弱口令也被接受。

### M2：原样导入仍补写空标题，规范同时规定相反的规整行为

- **位置**：`crates/keevo-core/src/import/mod.rs:701`；`spec/export.md:80`、`:93`、`:95`。
- **问题**：`Builder::finish` 无条件为合法空标题补写“导入的条目”或 URL 主机名。规范新增“不 trim、只受格式上限约束、超限整次失败”，后文却仍规定普通值 trim、每条目固定数量上限及超限丢弃。
- **前提**：正常导出再导入含空标题的条目；或其他实现据该规范实现读取方。
- **影响**：自有格式仍不能兑现名称保真；不同读取方可能接受、规整或拒绝同一文件。
- **严重程度**：**低**。
- **建议**：补写标题仅限规整模式；统一 §2，对全局资源上限、原样条目上限、第三方来源规整分别明确适用范围。
- **证据**：`review5c_m2_own_export_preserves_empty_title` 先用正常 API 创建并导出空标题，导入得到“导入的条目”，断言失败。条文矛盾可直接由上述行号核对。

### M3：迁移未完成时永久删除，再恢复旧备份仍重新授权

- **位置**：`crates/keevo-core/src/vault.rs:708`、`:1722`、`:1838`；`spec/ssh-agent.md` §4.1。
- **问题**：迁移中断、全局标记尚未写入时，永久删除会删除本机决定；恢复旧条目后，“无记录”再次触发旧 `unlocked` 属性迁入。`off` 只保护仍保有记录的条目。
- **前提**：迁移清理属性失败；用户明确关闭并永久删除密钥，随后在迁移完成前恢复旧备份。无需改写备份或掌握私钥。
- **影响**：已撤销密钥再次获得 `unlocked` 策略。测试证明策略复活，不声称已绕过其他来源检查完成签名。
- **严重程度**：**中**。
- **建议**：永久删除/重建对旧 ID 留下持久的关闭或迁移抑制记录，并与墓碑同事务；或在允许这些操作及恢复前可靠完成迁移。同步修订生命周期条文。
- **证据**：`review5c_m3_purge_during_incomplete_migration_survives_restore` 失败。故障仅注入本机迁移语句，恢复文件没有触发器；删除成功且策略消失后，恢复解锁又出现该策略。重建旧 ID 的记录也被删除，具有同一结构性缺口。

### M4：导出验证检查与使用之间仍可跨解锁代次

- **位置**：`crates/keevo-ffi/src/import.rs:242`、`:253`。
- **问题**：先短暂锁住核心取得 epoch，再独立消费验证标记，最后重新锁住核心导出；后两步之间使用的会话未重新核对。
- **前提**：存在尚未消费的导出验证，FFI 导出与建立新代次的解锁调用并发。
- **影响**：旧代次能力可被新代次的导出接受，未完整满足 C2。没有证明无需凭据导出，也没有证明当前 UI 可稳定触发此调度。
- **严重程度**：**低**（并发能力隔离不足）。
- **建议**：在持有同一核心会话锁时核对/消费验证并获取导出数据，统一锁顺序。
- **证据**：`review5c_m4_export_rechecks_epoch_when_consuming_authorization` 失败。测试持有验证标记互斥锁延迟消费，在导出线程读取 epoch 后，通过公开 `unlock` 建立新代次，再释放标记；导出成功。没有改写标记值；100 ms 等待用于安排线程调度，该反例已两次运行失败。

### M5：恢复后有效时间“不变小”的新增承诺不成立

- **位置**：`docs/sync.md:94`；`crates/keevo-store/src/restore.rs:303`；`crates/keevo-store/src/lib.rs:817`。
- **问题**：恢复后清空内存时钟，下一次以恢复数据库的最大 stored_ms 重建。旧备份只含本机已知的老修订时，时间会回退。
- **前提**：正常恢复旧备份，不需要攻击者。
- **影响**：不符合新文档；只会延后清理，**不会重新引入 L2 的提前清理**。
- **严重程度**：**建议**。
- **建议**：冻结前删除“不变小”，明确允许保守回退；无需为维持这句不必要承诺而改动存储模型。
- **证据**：`review5c_m5_restore_effective_clock_matches_documented_contract` 失败，模拟运行 100 天再恢复旧备份，有效时间从约 `8640000000 ms` 降为约 `0 ms`。

### M6：一个损坏条目会永久阻断后续健康条目的附件回收

- **位置**：`crates/keevo-core/src/vault.rs:1457`、`:1673`。
- **问题**：全库循环用 `?` 遇到首个错误立即结束；排序靠前条目的旧详情密文持续损坏时，每次解锁都停在同一处。
- **前提**：一个带附件条目的历史损坏；排序在其后的健康条目存在历史已清理、等待回收的无引用附件。
- **影响**：后者的附件可以一直残留并进入备份；不导致明文泄露或提前删除。
- **严重程度**：**低**。
- **建议**：按条目隔离失败并继续扫描，其自身仍按失败保留；可汇总错误供重试或诊断。
- **证据**：`review5c_m6_gc_continues_after_an_unreadable_item` 失败。两个条目的当前内容都可读；夹具模拟历史清理已提交及另一条目旧密文损坏，连续两次锁定/解锁后，健康条目的无引用附件仍存在。
