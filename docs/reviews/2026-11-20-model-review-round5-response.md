## 3. 回答评审的问题

1. **恢复年龄**：接受。从备份导入、而恢复前的数据库中没有的修订，保存时间记为恢复时的有效时间；两边都有的修订沿用恢复前的值。
2. **恢复失败状态**：选择**保持原来的解锁状态**。这与文档一直承诺的"失败时什么都不改变"一致：数据库在换入之前没有任何改动，没有理由改变内存中的状态。成功时照旧完整锁定。
3. **SSH 关闭策略的表示**：采用持久的 `off` 记录。迁移逐把可重入，全部完成后才写"已迁移"标记；永久删除与重建中的授权变化与墓碑在同一个事务中。
4. **自有格式往返**：承诺。除 export.md 列出的不导出内容外，Keevo 自己的格式往返后，字段值、名称与分区身份不变；导入构建器的"原样"模式不做任何来源专有的规整。
5. **不可读附件与重建**：区分两种情况。数据库错误等暂时性错误中止重建，什么都不改变。内容已损坏或缺失、永远读不出的附件不保留，并把名称返回给界面，由界面告诉用户。界面目前不提供逐个字段的选择，需要重建的条目又是只读的，中止重建会让用户无路可走。新增测试 `rebuild_reports_unreadable_attachments`。
6. **泄露检查的产品保证**：接受跨次交集分析这一残余风险，并在 governance §5 与开启前的确认中写明。"查过 / 未查过"已绑定到当前密码。响应正文有 1 MiB 的上限；取消正在进行的检查暂不提供，记入未决。
7. **独立导出向量**：完成。`spec/test-vectors/export-v1.json` 由独立的 Python 实现（argon2-cffi + libsodium）生成，内容如下。Rust 逐字节复现写出，并按期望的错误拒绝全部反例（`keevo-crypto` 的 `vectors::export_files`）。
   - 正例三个：普通 JSON、NFKD 等价的口令、空明文。每个都带固定的 KDF 参数、nonce、62 字节 AAD 与派生出的密钥。
   - 反例九个：口令错误，magic、版本、salt、nonce、密文、标签被改动，截断，KDF 参数不合法。
