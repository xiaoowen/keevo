# Keevo 产品设计

## 1. 愿景

> 让每个人都能不打折扣地掌控自己的全部数字秘密。

Keevo 是只属于你的数字保险库：
- 数据默认只存在你的设备上。
- 需要多设备时，通过你已经在用的 iCloud、云盘或自己的 NAS 同步，不需要额外运行任何服务。
- 存储数据的一方（Apple、云盘厂商，或任何能访问同步文件夹的人）都读不到你的数据。

我们想要 1Password 的精致与顺手，也想要 Bitwarden 的开放、透明与可自托管。

## 2. 核心理念与可执行原则

| 理念 | 可执行原则 | 可验证的约束 |
|---|---|---|
| 安全至上 | 默认即最安全。安全与便利冲突时先找两全的设计；找不到就选安全，并向用户解释原因 | 所有加密与协议设计先成文、经评审再编码；1.0 前完成第三方审计并公开报告 |
| 隐私设计 | 不收集，就不会泄露；元数据（标题、网址、标签）也是数据 | 默认零遥测；同步文件中只有不透明的密文，连"修改了哪些条目"都不暴露 |
| 本地优先 | 没有网络、没有账户、没有服务器，也能完整使用 | 所有功能离线可用；同步是可选能力，不是前提；每台设备都是完整副本 |
| 自托管 | 数据可以只放在你掌控的存储上 | 同步可以完全走 Syncthing、NAS 或外置硬盘，不经过任何第三方；官方自托管服务端暂缓（见 [future/self-hosted-server.md](future/self-hosted-server.md)） |
| 卓越体验 | 安全不能靠用户忍耐来实现 | 有明确的性能预算与关键流程时长目标（见 §6），每个里程碑都做可用性测试 |

### 我们不做的事

- 不做"由第三方帮你重置主密码"之类需要托管密钥的便利功能。
- 不在页面加载时自动填充，任何填充都必须由用户手势触发。
- 不引入广告、追踪 SDK 或第三方分析。
- 不自创密码学原语或协议。
- 初期不做团队与企业管理，避免过早引入密钥托管等复杂信任模型。

## 3. 目标用户

| 画像 | 痛点 | Keevo 的回答 |
|---|---|---|
| A. 注重隐私的个人用户 | 不信任纯云端的密码管理器；KeePass 类工具体验陈旧、同步麻烦 | 本地优先 + 精致的原生体验 + 开箱即用的 iCloud 端到端加密同步 |
| B. 开发者 | SSH 私钥散落在 `~/.ssh`；API Key 写在 `.env` 里容易被误提交；数据库密码躺在笔记软件里 | SSH Agent、`keevo run` 注入环境变量、`keevo://` 密钥引用、数据库凭证一等公民 |
| C. 自托管爱好者 | 不想把数据交给任何第三方，也不想多维护一个服务 | 同步到自己的 NAS 或 Syncthing 文件夹，不需要运行任何服务端 |

**首发聚焦 A 与 B 的交集**：使用 Mac 和 Chrome、在意隐私的开发者与技术用户。这群人能判断安全设计的好坏，也最可能成为早期贡献者。

## 4. 竞品定位

| 维度 | 1Password | Bitwarden | KeePassXC | **Keevo** |
|---|---|---|---|---|
| 源代码 | 闭源 | 开源 | 开源 | **全部开源** |
| 无账户本地使用 | 否（需账户，有离线缓存） | 否（需账户，有离线缓存） | 是（本地文件） | **是** |
| 同步方式 | 官方云 | 官方云或自托管服务端 | 自行用云盘同步数据库文件，冲突时整库合并 | **iCloud、任意云盘文件夹、Syncthing、NAS；无需服务端；条目级自动合并** |
| 抗同步数据泄露 | 账户密钥（2SKD） | 主密码 + KDF | 主密码（可加密钥文件） | **账户密钥（2SKD）+ 签名的设备日志链** |
| 体验精致度 | 极高 | 中 | 偏低 | **目标：对标 1Password** |
| 开发者能力 | SSH Agent、CLI、密钥引用 | SSH Agent、CLI、独立的 Secrets Manager | SSH Agent 集成 | **SSH Agent、CLI、密钥引用、环境变量、数据库凭证** |

**Keevo 的差异点**：开源 + 本地优先 + 无需服务端的端到端加密同步 + 精致体验 + 开发者原生。目前没有任何一款产品同时做到这五点。

## 5. 功能规格

### 5.1 核心概念

- **账户（Account）**：在本地创建，可选开启同步（iCloud 或文件夹）。包含密钥集，不包含邮箱等个人信息。
- **保险库（Vault）**：条目的容器。默认有一个"个人"保险库，可新建多个（如"工作"、"开发"）。每个保险库有独立密钥，为将来共享做准备。
- **条目（Item）**：由类型模板生成，由分区（Section）和字段（Field）组成。
- **附件（Attachment）**：挂在条目上的加密文件。
- **组织方式**：标签、收藏、归档、回收站（保留 30 天）。

### 5.2 字段系统

所有条目类型都建立在同一个字段系统上，任何条目都能添加自定义字段。

| 字段类型 | 默认隐藏 | 说明 / 特殊能力 |
|---|---|---|
| `text` | 否 | 单行文本 |
| `multiline` | 否 | 多行文本，支持 Markdown |
| `concealed` | 是 | 秘密值（密码、令牌等），可显示、复制、大字显示 |
| `email` / `url` / `phone` | 否 | 带格式校验；`url` 可点击打开 |
| `date` / `month_year` | 否 | 用于签发/过期时间，可触发到期提醒 |
| `select` | 否 | 枚举值（如数据库引擎、加密方式） |
| `totp` | 显示验证码 | 存储 `otpauth://` 参数，显示当前验证码与倒计时 |
| `ssh_private_key` | 是 | 查看/导出需要重新验证 |
| `reference` | 否 | 引用另一个条目（如数据库凭证引用 SSH 密钥条目作隧道） |
| `recovery_codes` | 是 | 恢复码列表，可逐个标记"已使用" |
| `kv_list` | 值隐藏 | 键值对列表（环境变量），每个值可单独标为秘密 |
| `file` | — | 引用附件 |

每个字段的属性：
- 稳定的 `id`：同步合并按字段 ID 进行。
- `label`、`type`、`value`。
- `purpose`：`username` / `password` / `otp` / `notes`，供自动填充识别。
- 是否参与自动填充。
- 是否需要重新验证才能查看。

用户可以把任意条目另存为**自定义模板**。

### 5.3 条目类型（首发）

| 类型 | 核心字段 | 特有能力 |
|---|---|---|
| **登录** | 用户名、密码、网址列表（每个网址可设匹配规则）、一次性密码、备注 | 自动填充；保存/更新提示；密码历史；"去修改密码"直达（`/.well-known/change-password`） |
| **电子邮件账户** | 邮箱地址、密码 / 应用专用密码、提供商、IMAP/POP3/SMTP 服务器与端口、加密方式、恢复邮箱/手机、恢复码 | 一键复制完整的客户端配置；常见提供商（Gmail、Outlook、QQ 邮箱、iCloud 等）自动填好服务器参数 |
| **安全笔记** | 标题、Markdown 正文 | Markdown 编辑与渲染；可加附件 |
| **SSH 密钥** | 私钥、公钥、指纹（SHA256）、算法、注释、可选口令、关联主机 | 生成 Ed25519 / RSA-4096 / ECDSA；导入 OpenSSH/PEM；SSH Agent；Git 提交签名；私钥导出需重新验证 |
| **API 凭证** | 提供商、Key ID / Client ID、Secret / Token、凭证种类、作用域、端点、环境、签发与过期时间 | 粘贴时按规则库识别提供商（如 `ghp_`、`AKIA`、`sk-` 前缀）；过期与轮换提醒。新建菜单里分"API 密钥"和"访问令牌"两个入口，底层同属 `api_credential` 类型的不同预设 |
| **数据库凭证** | 引擎（PostgreSQL / MySQL / MariaDB / SQL Server / MongoDB / Redis / 其他）、主机、端口、库名、用户名、密码、SSL 模式、连接参数、SSH 隧道（引用 SSH 密钥条目 + 跳板机） | 自动生成连接串（URI / JDBC / DSN）；可复制为 `keevo://` 引用 |
| **环境变量** | 名称、所属项目、多个环境配置（dev / staging / prod），每个配置是一组 `KEY=VALUE` | 导入/导出 `.env`；`keevo run` 注入；配合可安全提交到 git 的 `.env.keevo` 模板 |
| **双因素验证** | 发行方、账户名、TOTP 密钥（算法/位数/周期）、恢复码 | 屏幕二维码扫描；适用于密码不在 Keevo 中的账户（如公司 SSO） |

后续类型：信用卡、身份、软件许可证、Wi-Fi、银行账户、证件、服务器。

### 5.4 双因素验证（2FA）

- **标准**：TOTP（RFC 6238），支持 SHA-1/256/512、6/8 位、自定义周期；支持导入 `otpauth://` URI。HOTP 与 Steam 等变体放在后续。
- **添加方式**：
  - 扫描屏幕上的二维码：使用系统内容共享选择器，无需长期录屏权限。
  - 拖入二维码截图。
  - 粘贴 URI 或密钥。
  - 在 Chrome 扩展中"扫描当前页面"。
- **填充**：密码填充后，若下一步出现验证码输入框，直接提供同一条目的 TOTP，无需重新选择条目。可选"填充后自动复制验证码"。
- **恢复码**：逐个标记已使用；剩余少于 3 个时提醒。
- **安全取舍要讲清**：把密码和 TOTP 放在同一保险库，会降低两个因素的独立性。设置中说明这一点，并允许把 2FA 条目单独放进一个保险库。

### 5.5 开发者能力

**SSH Agent**
- Keevo 实现 SSH agent 协议，私钥永远不离开 Keevo。
- 每把密钥可设授权策略：每次使用都需批准 / 每个应用会话批准一次 / 解锁期间自动。
- 授权弹窗显示请求来源，例如"iTerm2 中的 `ssh git@github.com`"。
- 提供 `~/.ssh/config` 配置助手：先显示 diff，用户确认后才写入。

**Git 提交签名**：一键配置 `gpg.format=ssh`，使用保险库中的 SSH 密钥签名。

**命令行 `keevo`**：
```
keevo read "keevo://dev/openai/credential"
keevo run --env-file .env.keevo -- npm run dev
keevo inject -i config.tpl.yml -o config.yml
keevo item list|get|create|edit
keevo totp github
keevo generate --words 5
keevo lock
```
- CLI 通过桌面应用授权：用 Touch ID 授权，无需在终端输入主密码。
- 授权按终端会话划分。

**密钥引用**：
```
keevo://<保险库>/<条目>[/<分区>]/<字段>[?attribute=otp&profile=prod]
```
- 可以安全地写进代码库和配置文件，运行时才解析。
- 名称有歧义时报错，从不猜测。

**`.env.keevo` 模板**：只含引用、不含秘密，可以提交到 git，由 `keevo run` 解析。

**后续**：常用工具的 shell 插件（gh、aws 等）、CI 服务账号（需要自托管服务端）、本地密钥泄露自检（检查项目目录中是否存在保险库秘密的明文）。

### 5.6 安全中心

所有检查都在本地完成：

| 检查项 | 说明 |
|---|---|
| 弱密码 | 本地强度评估（zxcvbn 等价算法） |
| 重复使用 | 多个条目使用同一密码 |
| 已泄露密码 | 可选，默认关闭。使用 Have I Been Pwned 的 k-匿名接口：只发送 SHA-1 前 5 位，并开启响应填充 |
| 未启用 2FA | 对照本地内置的 2fa.directory 数据集，提示网站支持 2FA 但你尚未保存 TOTP |
| 即将过期 | API 凭证、令牌、证书到期提醒 |
| 不安全网址 | 保存的网址为 HTTP |
| 过时的 SSH 密钥 | RSA < 3072 位、DSA 等 |
| 恢复码不足 | 剩余恢复码过少 |

### 5.7 导入、导出与备份

- **导入**：1Password（1PUX）、Bitwarden（JSON，含密码保护的加密 JSON）、Chrome / Safari / Firefox CSV、KeePass（KDBX 4）、LastPass CSV。导入前预览，导入后可一键回滚。
- **导出**：Keevo 加密格式（推荐）、明文 JSON/CSV。明文导出需重新验证，并显示风险提示。
- **自动加密备份**：每日一次；导入、迁移、批量删除等重大操作前额外备份。备份与保险库同等加密，可指定外部位置。
- **应急包**：账户密钥 + 二维码 + 主密码书写处，PDF，引导打印保存。
- **后续**：支持 FIDO 联盟的凭证交换格式（CXF），与系统级导入导出对接。

## 6. 非功能需求

### 6.1 性能预算（以 1 万条目的测试保险库为基准）

| 指标 | 目标 |
|---|---|
| 冷启动到解锁界面 | < 1 s |
| Touch ID 通过到列表可用 | < 300 ms |
| 搜索每次按键的响应 | < 16 ms（一帧以内） |
| Quick Access 唤起 | < 150 ms |
| 扩展弹窗打开 | < 200 ms |
| 选中条目到完成填充 | < 150 ms |
| 主密码解锁（Argon2id） | 0.5–1.5 s，按设备校准 |

### 6.2 可靠性

**不丢数据是第一可靠性目标**：
- 条目历史版本。
- 回收站保留 30 天。
- 自动加密备份。
- 格式迁移前自动备份。
- 所有写入在单个事务内完成。
- 强制断电后数据不损坏。
- 开启同步后，每台设备都是完整副本；同步文件夹被误删或回滚时，任何一台设备都能把数据补回来。

### 6.3 平台

- macOS 15+。优先支持 Apple Silicon；Intel 视维护成本最多支持到 macOS 26（最后一个支持 Intel 的版本）。
- Chrome 及 Chromium 系浏览器（Edge、Brave、Arc、Vivaldi）。

### 6.4 可访问性与国际化

- VoiceOver 全覆盖、全键盘操作、对比度达到 WCAG AA。
- 首发简体中文与 English，字符串全部外置。

## 7. 成功指标（不依赖遥测）

在零遥测的前提下，我们这样衡量：
- **体验**：定期做可用性测试，目标如下：
  - 新用户 5 分钟内完成首次网页自动填充。
  - 从 1Password / Bitwarden 迁移 10 分钟内完成。
  - 关键任务成功率 ≥ 90%。
- **采用**：下载量、Chrome 应用商店安装量、GitHub 活跃度、自愿问卷。
- **安全**：审计无未修复高危问题；漏洞响应满足 SLA（见 [governance.md](governance.md)）。
- **质量**：自动填充回归语料库识别率；崩溃与数据问题报告数（用户主动提交）。
